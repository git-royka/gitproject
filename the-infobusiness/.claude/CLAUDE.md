# Контекст проєкту: календар подій для Telegram-клубу (Mini App)

## Що це

Закритий Telegram-клуб з форум-гілками (topics). Складається з трьох частин:
1. Закріплений пост-путівник для нових учасників (ще не написаний/не опублікований)
2. Telegram Mini App — стрічка подій місяця (без сітки-календаря): перемикання місяців стрілками, тема місяця під назвою, нижче список подій з датою/часом/фото/описом, кольорове кодування типів подій, кліком по події — перехід у конкретне повідомлення в потрібній гілці
3. Бот (Telegraf, задеплоєний як Vercel serverless-функції з webhook) — показує кнопку календаря по `/start` і `/calendar`, чистить службові повідомлення форуму, і роздає фото подій через медіа-проксі

Репозиторій: `https://github.com/git-royka/gitproject` (гілка `master`).
Робоча папка: `the-infobusiness/` в корені репо. `index.html`, `events-template.csv`, `package.json` лежать flat; бот — у `server/bot.js`, серверні ендпоінти Vercel — у `api/`.

## Файли

### `the-infobusiness/index.html`
Статичний HTML/JS без білд-кроку, задеплоєний на Vercel: **https://the-infobusiness-calendar.vercel.app/**
- `telegram-web-app.js` (CDN) для теми й `openTelegramLink()`
- PapaParse (CDN) тягне події з опублікованої як CSV Google Таблиці
- **UI (з 2026-09-10): без сітки-календаря.** Шапка — стрілки ‹›, назва місяця, під нею тема місяця. Нижче — стрічка (`#feed`) усіх подій обраного місяця, згруповані по даті (`feed-day-section` / `feed-day-label`), кожна подія — картка з кольоровою крапкою типу, назвою, часом, фото (`summary-media`) і описом
- Посилання на повідомлення: `https://t.me/c/<chat_id_без_-100>/<thread_id>/<message_id>`

Налаштування вгорі файлу — **вже заповнені реальними значеннями**:
```js
const SHEET_CSV_URL = "https://docs.google.com/spreadsheets/d/e/2PACX-1vRNVvcFM2b1rwEbHu2TGk8Yx92GM8aVzs5sB727h8PRsRwV4xMWixHGe5QSf13jcyYEP_2-v3ed9Ex3/pub?gid=409438120&single=true&output=csv";
const CHAT_ID = "-1004459521892";
```

**Тема місяця (з 2026-09-10, наступна сесія): читається з колонки `theme` Google Таблиці, а не тільки захардкожена.**
Пріоритет: `sheetThemes[YYYY-MM]` (побудована з колонки `theme` під час парсингу CSV, ключ — рік-місяць з `row.date`) → фолбек `MONTH_THEMES` в `index.html` (ключ — номер місяця 0–11, без прив'язки до року). Адміну таблиці достатньо заповнити колонку `theme` в **одному будь-якому рядку** потрібного місяця — решту рядків того ж місяця лишати порожніми в цій колонці. Якщо в таблиці для місяця нічого не заповнено (або в місяці взагалі нема подій), покажеться значення з `MONTH_THEMES` (зараз заповнено для вересня–січня: «АІ в інфобізнесі», «Воронки, що продають», «Продажі та конверсія», «Системний інфобізнес», «Трафік і масштабування»).

**Банер "скоро будуть події" (з 2026-09-14):** для місяців без жодної реальної події можна показати банер замість тексту "подій ще немає". Додається одним рядком у тій самій таблиці з `type=banner` — `date`, `thread_id`, `theme` йому не потрібні, лише `title` (текст під картинкою) і `message_id` (повідомлення з фото, можна з прихованої гілки — медіа-проксі дістає файл за `message_id` незалежно від гілки). Такий рядок парситься окремо (`comingSoonBanner` в `index.html`) і показується в БУДЬ-ЯКОМУ місяці без подій, поки в ньому нема жодного реального рядка з `title`.

### `the-infobusiness/events-template.csv`
Шаблон/референс структури таблиці подій (не використовується напряму рантаймом — джерело даних це опублікований Google Sheets CSV вище). Колонки:
```
date,title,type,time,thread_id,message_id,summary,theme
2026-08-20,Розбір домашки,lesson,19:00,16,41,Розбираємо домашні завдання учасників та відповідаємо на питання,АІ в інфобізнесі
2026-08-27,Прямий ефір з гостем,stream,20:00,16,41,Гостьовий ефір з експертом галузі,
,Зовсім скоро тут будуть нові події 🚀,banner,,,187,,
```
`theme` — необов'язкова колонка, заповнюється лише в одному рядку на місяць (див. вище).
Останній рядок — приклад банера (`type=banner`), `message_id=187` тут умовний.

### Бот і серверна частина (Node.js, Telegraf) — **вже задеплоєно на тому ж Vercel-проєкті, що й `index.html`**, як serverless-функції, а не окремий процес
- `the-infobusiness/server/bot.js` — логіка бота: вітальний текст і кнопка "Календар подій" (`/start` в приваті, команда `/calendar` в чаті — звичайна URL-кнопка на `t.me/<бот>/<app>`, не web_app-кнопка, бо та не працює в групах), автовидалення службових повідомлень форуму (join/leave/pin/закриття-відкриття теми/видимість General), і `getMediaBytes()` — дістає file_id фото/відео з повідомлення чату через `forwardMessage` у приватний storage-чат бота (`STORAGE_CHAT_ID`), тоді качає байти з Telegram File API
- `the-infobusiness/api/webhook.js` — Vercel-функція, приймає POST від Telegram (webhook, не polling), перевіряє `X-Telegram-Bot-Api-Secret-Token` проти `WEBHOOK_SECRET`
- `the-infobusiness/api/media/[messageId].js` — Vercel-функція `GET /api/media/:messageId`, віддає байти фото/відео через `getMediaBytes()` — саме цей ендпоінт смикає `index.html` (і тепер банер) для показу фото подій
- Токен бота (`BOT_TOKEN`), `CHAT_ID`, `STORAGE_CHAT_ID`, `WEBHOOK_SECRET` — змінні середовища у Vercel (НЕ в git, `.env` в репо відсутній)

### `the-infobusiness/package.json`
Залежність: `telegraf`. Немає `vercel.json` — Vercel сам розпізнає `api/*.js` як serverless-функції за конвенцією.

## Що ще не зроблено / наступні кроки

1. **В реальній Google Таблиці додати колонку `theme`** (в аркуші "events-template", `gid=409438120`) і заповнити тему в одному рядку кожного місяця — код це вже підтримує, треба тільки додати колонку в саму таблицю
2. **Додати рядок банера** (`type=banner`) для місяців без подій — відправити фото-повідомлення в приховану головну гілку, взяти його `message_id`, вписати в новий рядок таблиці разом з текстом у `title`
3. Наповнити Google Таблицю реальними подіями клубу (замість тестових рядків)
4. **BotFather**: перевірити, чи прив'язаний Mini App до бота (`/newapp`, URL — https://the-infobusiness-calendar.vercel.app/) — не підтверджено в поточній сесії
5. Написати й закріпити пост-навігацію в групі з посиланнями на гілки

## Технічні рішення (свідомо обрані, не змінювати без потреби)

- Статичний HTML без білд-кроку (не React) — простіше деплоїти, менше залежностей
- Дані подій через публічний CSV з Google Sheets, а не API з ключем — щоб уникнути серверної частини й спростити ротацію подій нетехнічним адміном клубу
- `thread_id` дорівнює номеру найпершого повідомлення гілки (стандартна поведінка Telegram forum topics)
- Токен бота — тільки в `.env` бота, ніколи в коді фронтенду
